# 《午休快跑》设计文档

- 日期：2026-10-13（第 1 版）
- 状态：待审阅
- 工程名：`retro_run`（project.config.json 的 projectname；存档 key 前缀 `retro-run.`）
- 游戏名：暂定《午休快跑》，正式名在 M3 前确定
- 一句话：2000 年代初的初中生，午休回家偷偷玩一会儿电脑，然后赶在打铃前一路狂奔回学校。

---

## 1. 定位与约束

| 项 | 决定 |
|---|---|
| 平台 | 抖音小游戏（原生工程 `douyinProjectType: native`），所有 `tt.*` 调用集中在 `js/platform.js` |
| 形态 | 竖屏（`deviceOrientation: portrait`），单手操作，一局约 2 分钟，失败后一键重来 |
| 技术 | 和 `nine_to_nope` 一样：纯 JS + Canvas 2D + CommonJS `require`，不用引擎 |
| 美术 | 像素风；所有素材在代码里定义（调色板 + 字符矩阵），不依赖图片文件（见第 9 节） |
| 年代 | 2000–2003 年：大头 CRT 显示器、拨号上网、Win98 风格桌面、街边小卖部 |
| 变现 | 第一版不做，也不预留广告位 |
| 排行 | 第一版不做 |

**情感目标**：让玩过那个年代的人有"这就是我"的感觉。紧张来自"再玩一会儿"和"要迟到了"之间的拉扯；温暖来自路上那些没人要求、但你选择去做的小事。

**成功标准（第一版）**：
- 新玩家 10 秒内明白"什么时候关电脑由我决定，然后要跑回学校"
- 每天在电脑前都纠结"再等一下还是现在就走"
- 跑步段有速度感和"差一点就迟到"的紧张
- 第一次碰到好人好事时，玩家是真的在犹豫（因为不知道帮了会怎样）
- 看到屏幕上的致敬游戏时，玩过的人能一眼认出来

---

## 2. 一局的流程（一局 = 一天的午休）

```
家里（第一人称）            出门转场          跑步（2.5D 伪 3D）            校门
看电脑 → 决定关机 → 关机等待 → 换鞋锁门 → 一路跑，路口选路线 → 到校 / 迟到 → 结算
└─────────────── 同一个午休时钟从头走到尾（12:25 → 13:00 打铃）────────────────┘
```

### 2.1 时钟

- 游戏内时间从 **12:25** 开始（已经吃完饭坐到电脑前），**13:00** 打预备铃。
- 换算：**1 游戏分钟 = 3 秒**，所以整局最多 105 秒，加上转场和结算大约 2 分钟。
- 时钟在家里和跑步段**连续走，不会重置**。在家多待一分钟，路上就少一分钟。
- 屏幕左上角一直显示电子表样式的时间（例如 `12:41`），12:55 之后数字变红并闪烁。

### 2.2 胜负

| 情况 | 结果 |
|---|---|
| 13:00 前进校门 | **过关**，按过瘾值和剩余时间评星 |
| 迟到，但路上做过至少一件好人好事 | **过关**，进入"迟到但温暖"的特别结局 |
| 迟到，也没做好人好事 | **失败**：被值周老师拦下罚站，可以重来 |

好人好事能让迟到也过关这件事，**游戏里任何地方都不提前说**。玩家只有真的做了、又真的迟到了，才会发现。

## 3. 家里：第一人称电脑段

### 3.1 画面（竖屏，从上到下）

- **上部（约 60%）**：一台大头 CRT 显示器，屏幕是 4:3。屏幕里显示当天的致敬游戏画面（像素重绘、会动），右下角是 Win98 风格的任务栏和时钟。
- **中部**：显示器下沿、键盘、鼠标垫和一杯喝了一半的汽水。屏幕的光照亮桌面。
- **下部**：一个"关机"按钮（做成机箱电源键的样子）。
- 背景是家里的墙，墙上挂着日历和奖状，窗外是中午的阳光。

### 3.2 玩家做什么

玩家**不操作屏幕上的游戏**，只决定什么时候关机。电脑前的时间会积累**过瘾值**，屏幕上会不断出现诱惑。

- **过瘾值**：在电脑前每过 1 游戏分钟 +10。
- **诱惑节点**：每天 3–4 个，按时间线出现。屏幕上弹出一个带进度的诱惑（例如"还差 120 经验升 35 级"，进度条在涨），持续 1–3 游戏分钟。**等到它完成**再关机，过瘾值一次性 +50～+100；**半路关机**就拿不到。越往后的诱惑奖励越高，需要等的时间也越长。
- 诱惑节点的时间、长度、奖励写在每天的数据里（见第 7 节），同一天每次玩都一样，玩家可以慢慢摸清"最贪能贪到哪一步"。

### 3.3 关机

1. 点电源键 → 屏幕出现 Win98 风格的"关闭计算机"对话框，再点"确定"。
2. 屏幕显示"正在关闭计算机……"，**等待 1～2 游戏分钟**（随机）。
3. 小概率（20%）出现"程序没有响应"，需要再点一次"结束任务"，额外等 0.5 游戏分钟。
4. 屏幕变黑，CRT 的亮线收成一个点消失，并播放"啪"的一声。

这几步本身就是"想走却走不了"的那种焦急，也是年代感的来源。

### 3.4 出门转场

黑屏 → 换鞋、锁门、下楼的三格像素快剪（共 2 秒，不消耗游戏时间）→ 镜头切到楼下街道，学生背对镜头，倒计时 HUD 出现，开始跑。

## 4. 跑步段：2.5D 伪 3D 冲刺

### 4.1 画面

- 竖屏，镜头在学生**背后斜上方**。路面是用透视绘制的伪 3D 道路（同老式赛车游戏），两边的店铺、电线杆、行人都是像素精灵，从远处迎面而来、逐渐变大。
- 路面分 **3 条道**。平时的路段可以有缓弯（路面往一边弯），让街道看起来不那么死板。
- HUD：左上角是时间，右上角是零花钱，底部是体力条。

### 4.2 操作

| 操作 | 效果 |
|---|---|
| （无操作） | 自动以正常速度往前跑 |
| 左右滑 | 换道 |
| 上滑 | 跳（跳过水坑、倒地的自行车、小狗） |
| 下滑 | 钻、蹲（钻过晾衣杆、半开的卷帘门） |
| 长按 | 冲刺，速度 ×1.5，消耗体力 |

### 4.3 体力

- 体力满值 100。冲刺时每秒消耗 25；不冲刺时每秒恢复 8。
- 体力降到 0：学生弯腰喘气 1.5 秒，这期间速度只有正常的一半，结束后体力恢复到 30。
- **补给**：路边小卖部和摊点可以买东西，跑过时点一下摊位即可购买（会停下 0.5 游戏分钟）：
  - 冰棍 ¥0.5：体力回满
  - 汽水 ¥1：体力回满，并且接下来 10 秒冲刺不消耗体力
- 零花钱每天 **¥1.5**，不累积到第二天。

### 4.4 碰撞与惩罚

- 撞到障碍**不会死**，只会摔倒或被挡住，**损失时间**：学生摔倒、爬起来，时钟额外走 0.5～1 游戏分钟，同时屏幕轻微抖动。
- 整个游戏唯一的失败方式就是迟到。

### 4.5 路口与路线

**地图**：家到学校之间有 **2–3 个路口**，组成 **3–4 条可选路线**。

```
          家
          │
       ┌─路口1─┐
     大路      菜市场
       │        │
     路口2 ─────┤
     │    └─ 铁路桥小巷
     │          │
   学校正门   学校后门
```

| 路线 | 路程（正常速度跑完需要） | 特点 |
|---|---|---|
| 大路 → 正门 | 约 13 游戏分钟 | 最稳：红绿灯、自行车流、早点摊 |
| 大路 → 铁路桥小巷 → 后门 | 约 11 游戏分钟 | 有道口栏杆（看运气要不要等火车）、小狗、晾衣杆 |
| 菜市场 → 正门 | 约 10 游戏分钟 | 人多拥挤、三轮车、积水，摊位多（容易补给） |
| 菜市场 → 铁路桥小巷 → 后门 | 约 9 游戏分钟 | 最近也最乱，好人好事的彩蛋也最常出现在这里 |

具体数字在 M2 试玩后再调。

**路口的表现**：
- 快到路口时，前方出现十字或丁字路口，每个方向都有路牌或标志性店面（"菜市场""铁路桥"），并显示 2 秒的方向箭头提示。
- 在路口判定区内左右滑就转弯；不操作就走默认方向（直行或靠右）。
- 转弯动画 0.3 秒：画面整体往一侧甩，新街道从另一侧转进来，然后继续跑。不做真的 3D 旋转。

### 4.6 阻碍一览

| 阻碍 | 应对 | 出现的路线 |
|---|---|---|
| 红绿灯 | 红灯时跑到停止线会自动停下，等绿灯（最多 1 游戏分钟）；在停止线前长按冲刺就是闯红灯，会被路口的交警叔叔拦下"教育"，损失 1.5 游戏分钟 | 大路 |
| 自行车流 | 换道躲开 | 大路 |
| 倒在路上的自行车 | 跳 | 大路、小巷 |
| 三轮车 | 换道躲开（占两条道） | 菜市场 |
| 人群 | 只能慢慢挤过，速度减半，冲刺无效 | 菜市场 |
| 积水 | 跳；踩进去会滑倒 | 菜市场、小巷 |
| 晾衣杆、卷帘门 | 钻 | 小巷 |
| 小狗 | 跳过，或者绕开；被追上会被吓得摔倒 | 小巷 |
| 道口栏杆 | 随机：有时直接通过，有时要等火车过去（约 1 游戏分钟） | 铁路桥 |
| 修路 | 某一天某条道整段封闭，只能走另一条 | 每天随机一处 |

每天出现哪些阻碍、出现在哪里，由当天的种子决定（见 10.3），同一天每次玩都一样。

## 5. 好人好事彩蛋

### 5.1 原则

- **不提示**：没有"任务"字样、没有感叹号图标、没有奖励说明。
- **只用画面表达**：需要帮助的人或动物有明确的视觉状态（老奶奶站在斑马线前犹豫、小猫在树上发抖、小孩站在路边哭），玩家看得懂就行。
- **跑过去就错过**：要帮就得**主动停下**（跑进那条道并碰到对方，或者点一下对方）。没碰上，这件事就过去了，不会再出现。
- **一定花时间**：每件好事都要消耗 1.5～4 游戏分钟，基本上做了就会迟到或差点迟到。

### 5.2 第一版的事件

| 事件 | 触发方式 | 帮忙时的互动 | 耗时 |
|---|---|---|---|
| 扶老奶奶过马路 | 大路红绿灯处，30% 概率 | 按住屏幕，陪老奶奶慢慢走过斑马线，松手就停 | 3 游戏分钟 |
| 救树上的小猫 | 小巷，25% 概率 | 连点屏幕爬树，抱下小猫交给旁边的小妹妹 | 2 游戏分钟 |
| 帮迷路的小弟弟找妈妈 | 菜市场，25% 概率 | 牵着他在菜市场里跑（这段路速度减半），直到找到他妈妈的摊位 | 2.5 游戏分钟 |
| 帮推三轮车上坡 | 铁路桥坡道，20% 概率 | 连点屏幕把三轮车推上坡 | 1.5 游戏分钟 |

每天最多出现 2 件，由当天种子决定是哪几件。

### 5.3 结果

- **做了好事、按时到校**：结算时额外一行小字，例如"今天好像有个老奶奶在打听你是哪个班的"，并解锁一枚隐藏徽章。
- **做了好事、迟到了**：特别结局。值周老师正要记名字，被帮助的人（或者他的家人）刚好赶到校门口说明情况，老师摆摆手让你进去。结算卡标题是"迟到了，但没关系"。
- 周五的周结算会把这一周帮过的人都画在一张"感谢卡"上（见 6.2）。

### 5.4 灰色事件（M2 再做，第一版只做一个）

不是黑白分明的好坏选择，体现真实的初中生活：
- **小卖部多找了钱**（第一版做这个）：买冰棍时老板多找了 ¥1。要还的话就得掉头回去（0.5 游戏分钟）；不还，多出的 ¥1 当天可以花。不还没有任何惩罚，周五的周结算里会多出一句老板的念叨。
- 以后可以加：同学喊你帮他带作业、看到低年级被欺负。

## 6. 一周结构（主线）

### 6.1 周一到周五

每天屏幕上致敬一款不同的游戏，诱惑和阻碍的强度逐天提高。通过当天就解锁下一天。

| 哪天 | 致敬对象 | 屏幕上的标志性画面（像素重绘） | 诱惑节点举例 |
|---|---|---|---|
| 周一 | 石器时代 | 原始人骑着宠物恐龙，回合制战斗 | "宠物快抓到了！再扔一次" |
| 周二 | 传奇 | 一群战士和法师在城门口攻城，满屏特效 | "还差 120 经验升级""地上爆了件装备" |
| 周三 | CS | 第一人称持枪，角落是比分和回合倒计时 | "炸弹已安放""这局 15:14，赢了再走" |
| 周四 | 红警 | 俯视地图，坦克集群，矿车采矿 | "敌方坦克快打到基地了，再守一波" |
| 周五 | 魔兽争霸 | 农民伐木，英雄带兵团战 | "英雄马上升级""同学弹窗：周五晚上包宿去不去" |

### 6.2 周五的周结算

周五到校后，出现一张"本周总结"卡：
- 每天的星级
- 这一周帮过的人（像素头像排成一排，每人一句话）
- 班主任评语，按这一周的表现从几种里选一种（全部准时、多次迟到但做了好事、从没做过好事等）

### 6.3 星级

每天按"过瘾值 + 到校时剩余的游戏分钟 × 20"算分，达到当天的分数线得 1/2/3 星。分数线在每天的数据里配置。

## 7. 致敬与版权

- **不用原作名字、Logo、截图、音频**。名字用谐音或改字，画面用像素重绘最有标志性的场景，音乐用自己合成的 8-bit 风格。
- 诱惑台词可以用玩家熟悉的梗，但不直接引用原作文本。
- 同样处理其他商标：不出现"QQ""Windows"字样，用"企鹅弹窗""开始菜单"之类的造型暗示。
- 正式提审前，查一遍抖音小游戏对致敬、戏仿内容的审核规则。
- 五款致敬游戏的谐音名在 M3 开始前定下来，写进 `js/data/days.js`。

## 8. 其他界面

- **标题页**：一张像素风的初中校门，铃声响起，标题落下。点击开始。
- **周历**：一张作业本风格的周一到周五课程表，每天一格，显示星级和锁定状态；点格子开始那一天。
- **到校演出**：校门口，按时到校是冲进铁门、值周生让开；迟到时铁门正在关，值周老师拿着本子站在门口。
- **结算卡**：当天的过瘾值、到校时间、星级，以及好人好事和灰色事件带来的额外文字。按钮：再来一次、下一天。

## 9. 美术：像素风 + 代码定义素材

- **低分辨率画布**：所有内容先画在 **180×320** 的离屏画布上，再整数倍放大到屏幕（关闭平滑），保证像素锐利。屏幕比例不是 9:16 时，上下或左右留出背景色边。
- **素材格式**：每个精灵写成一个 JS 对象：调色板（字符 → 颜色）+ 若干帧字符矩阵。例如：

```js
module.exports = {
  palette: { '.': null, 'k': '#2c2c2a', 's': '#f5c4b3', 'r': '#e24b4a', 'w': '#f1efe8' },
  frames: [
    [
      '...kkkk...',
      '..kkkkkk..',
      '..kssssk..',
      // ...
    ],
  ],
};
```

- **缓存**：启动时把每个精灵的每一帧画到各自的离屏画布上并缓存，绘制时直接 `drawImage`。
- **可替换**：渲染器通过素材名取图（`sprites.get('student.run', frame)`），素材表里每个名字可以对应代码定义的像素数据，也可以对应一张图片。以后找美术重画，只需改素材表，不需要改渲染代码。
- **整体调色板**：控制在 32 色以内，偏暖、略微褪色，像旧照片。电脑屏幕里的游戏画面可以用更饱和的颜色，和现实世界区分开。
- **伪 3D 精灵缩放**：远处的精灵按距离缩小后再画到低分辨率画布上，统一用最近邻缩放，保证不糊。

## 10. 技术架构

### 10.1 工程结构

```
game.js               入口：require('./js/main')
game.json             { "deviceOrientation": "portrait" }
project.config.json   douyinProjectType: native；packOptions 忽略 test/、docs/、tools/
package.json          只放 test 脚本
icon.png
audio/                音效和背景音乐 mp3（由 tools/gen-audio.cjs 生成后提交）
tools/
  gen-audio.cjs       8-bit 音频合成脚本（复用 nine_to_nope 的做法），不打包进游戏
js/
  main.js             组装模块、绑定事件、主循环（输入 → 引擎 → 事件 → 渲染/音效）
  config.js           全局常量：时钟换算、体力参数、颜色、音效表、存档 key
  platform.js         tt.* 适配：画布、安全区、触摸、存储、音频、震动、生命周期
  util.js             clamp / lerp / createRng / pickWeighted / 缓动
  input.js            手势识别：滑动方向、长按、点击
  audio.js            音效池 + 背景音乐切换
  data/
    days.js           五天的配置：致敬游戏、诱惑时间线、种子、分数线、阻碍强度
    map.js            路口和路段的图：每段的长度、弯道、可出现的阻碍和事件
    obstacles.js      阻碍定义：占哪几条道、应对方式、惩罚时间
    deeds.js          好人好事和灰色事件：触发条件、概率、互动方式、耗时、结算文字
    shops.js          补给物品和价格
  engine/
```

### 10.2 约定（和 nine_to_nope 保持一致）

- 数据写成 JS 模块，用 `require` 引入。
- **引擎不碰平台和绘制**：用 `on/emit` 往外发事件，主循环调用 `update(dt)`，单帧 `dt` 最多 0.1 秒。
- **渲染器只读快照**：`renderer.draw(engine.view(), now, dt)`；`renderer.hitTest(x, y)` 只负责把坐标翻译成动作。
- **切到后台自动暂停**。
- **可复现**：所有随机都来自 `createRng(seed)`，每天的种子固定写在 `days.js` 里；引擎内部只用累计的 `dt`，不调用 `Date.now()`。

### 10.3 关键设计

- **一个时钟贯穿全局**：`clock.js` 是唯一的时间来源。家里段和跑步段都往它报告"过了多少真实秒"，惩罚和好人好事用 `clock.spend(游戏分钟)` 扣时间。胜负只看到达校门时 `clock` 的读数。
- **轨道和渲染分离**：`track.js` 只产出"第 N 米处有什么"（路段弯曲度、物件、所在道、路口），不知道怎么画；`road.js` 负责把它投影成伪 3D 画面。碰撞判定在引擎里按"距离 + 道"做，和投影无关。
- **路口**：`track.js` 把路口表示成轨道上的一个特殊段，带若干出口。跑步者进入判定区后，引擎根据输入（或默认方向）选择出口，`track` 接上对应的下一段路，同时发出 `turn` 事件让渲染器播放转弯动画。
- **好人好事**：`deeds.js` 只管某件事是否出现、互动进度和耗时；触发出现由 `track` 在生成路段时按种子和概率决定。结算时引擎看"是否迟到 + 是否做过好事"给出结局类型。
- **家里段**：`home.js` 按 `days.js` 的诱惑时间线推进诱惑节点，记录哪些完成了。关机流程是一个小状态机（确认 → 关机等待 → 可能的"程序没有响应" → 黑屏）。

## 11. 测试

- **单元测试**（`node --test "test/**/*.test.cjs"`），用固定种子和固定步长的 `dt` 驱动：
  - 时钟：换算、扣时间、13:00 判定边界
  - 家里段：过瘾值累积、诱惑节点完成和半路放弃、关机等待和"程序没有响应"
  - 跑步者：换道边界、跳和钻的时长、冲刺消耗、体力耗尽后的喘气和恢复、补给效果
  - 轨道：同一种子生成相同的路段和物件；路口选择接上正确的下一段；修路封道
  - 碰撞：每种阻碍的正确应对不扣时间、错误应对扣对应时间
  - 好人好事：概率触发可复现、互动完成和中途放弃、每天最多 2 件
  - 胜负：按时、迟到加好事、迟到无好事三种结局
  - 存档：版本迁移、解锁进度
- **渲染冒烟测试**：用假 Canvas 上下文跑完整一局，确保各场景、各精灵都能绘制；检查所有精灵数据的行宽一致、用到的字符都在调色板里。
- **浏览器预览**：用浏览器模拟 `tt` 接口，在内置浏览器里按手机尺寸运行游戏，截图检查画面（不提交，开发时用）。
- **真机验证**：每个阶段结束时在抖音开发者工具和真机上试玩，并由 Rainman 评估手感。
